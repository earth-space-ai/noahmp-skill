# Debugging Noah-MP and HRLDAS

A field guide to the most common Noah-MP failure modes, compile errors,
runtime crashes, water-balance violations, and how to diagnose them quickly.

---

## 1. Compile errors

### `cannot find -lnetcdff` / `Symbol not found: __netcdf_MOD_*`

netCDF Fortran bindings missing or built with a different compiler than your
HRLDAS build.

```bash
# Sanity check
nf-config --flibs        # should print -lnetcdff -lnetcdf ...
nf-config --fflags       # include path

# Fix
$EDITOR user_build_options
# set NETCDFLIB = -L$(nf-config --prefix)/lib -lnetcdff -lnetcdf
# set NETCDFMOD = -I$(nf-config --prefix)/include
make clean && make
```

### `cannot find -ljasper`

Jasper not installed. macOS: `brew install jasper`. Ubuntu:
`sudo apt-get install libjasper-dev`. Then update `LIBJASPER` and
`INCJASPER` in `user_build_options`.

### `make` succeeds but `hrldas.exe` missing

Earlier silent build error in the submodule. Always rebuild from clean and
inspect the log:

```bash
make clean && make >& compile.log
grep -i error compile.log | head
# typical first error is in noahmp/src/, often a missing module dependency
```

### `create_forcing.exe` missing, no "forcing" in compile.log

OK in some configurations, the NLDAS pre-processor is intentionally
skipped. You can still run single-point cases. To force-build it, see the
HRLDAS docs.

### Strange link errors after editing `user_build_options`

Object files from the old build linger. Always:

```bash
make clean
make
```

Never partial-rebuild after changing compiler flags or library paths.

### See also

- HRLDAS compilation FAQ: https://github.com/NCAR/hrldas/discussions/72
- WRF library install (jasper + netCDF):
  https://www2.mmm.ucar.edu/wrf/OnLineTutorial/compilation_tutorial.php#STEP2

## 2. Runtime crashes

### `cannot open ... LDASIN`

INDIR points to the wrong directory. Either `create_forcing.exe`
(2D/NLDAS) or `create_point_data.exe` (single-point) hasn't been run, or
its output went somewhere else.

```bash
ls -la $INDIR    # should contain LDASIN_DOMAIN1.YYYYMMDDHH.nc files
```

### `cannot open ... HRLDAS_setup`

Same root cause. The `HRLDAS_setup_<date>_d1` file is generated by the
forcing pre-processor and must match the START date in the namelist.

### Run hangs or extremely slow

For 2D MPI runs, check that you actually built MPI (`./configure` option 4
or 6) and are launching with `mpiexec` / `mpirun`. A serial `hrldas.exe`
launched serially on a CONUS domain looks like a hang for the first
several hours.

### Restart file mismatch

```
Error: restart variable X not in restart file
```

You changed physics options between the original run and the restart, and
the new option requires a state variable the old restart doesn't have.
Cold-start (comment out `RESTART_FILENAME_REQUESTED`) and re-spin.

## 3. Output looks wrong

### `LH` is zero or constant year-round

`DYNAMIC_VEG_OPTION` mismatched with how LAI is supplied. Options 1 and 4
expect prescribed LAI; 2/3/5/6 expect dynamic LAI. Check `README.namelist`
for your version.

### Soil moisture frozen all year

`FROZEN_SOIL_OPTION` set incorrectly, or `STC` initial states are below
freezing. For warm-region simulations, set `FROZEN_SOIL_OPTION = 1` and
verify `STC` initial values in the wrfinput.

### Water balance violation in the log

`BalanceErrorCheckMod.F90` writes a per-timestep diagnostic. If you added a
new water reservoir, you likely need to extend `BalanceErrorCheckMod.F90`
to account for it.

### Output has the right shape but the values are wrong

If you added a new variable via `custom-output.md` and the output is all
`undefined_real`: `*OutTransferMod.F90` line missing. If it's all the
initialization value: `*InTransferMod.F90` line missing. Both files must be
edited symmetrically. See `custom-output.md`.

## 4. Helpful diagnostics

### Read a NetCDF output file at the command line

```bash
ncdump -h YYYYMMDDHH.LDASOUT_DOMAIN1     # header only
ncdump -v BTRANXY YYYYMMDDHH.LDASOUT_DOMAIN1 | head -50
```

### Compare two output files variable-by-variable

```bash
nccmp -df run_a.nc run_b.nc              # data + header diff
# Or with cdo:
cdo diff run_a.nc run_b.nc
```

### Check restart contents

```bash
ncdump -h RESTART.YYYYMMDDHH_DOMAIN1
```

### Inspect the source tree status

```bash
cd hrldas
git status
cd noahmp
git status
git log --oneline -10
```
